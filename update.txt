## DÉTAIL TECHNIQUE ET FEUILLE DE ROUTE DE CHAQUE RÉVISION

### [x] REV-01 : Correction du Pyodide Web Worker (Erreur "Classic web workers")
* **Problème identifié :** Message d'erreur *"Erreur : Classic web workers are not supported"* bloquant l'exécution du code Python dans le navigateur.
* **Cause racine :** Pyodide v0.26+ intègre une détection stricte `isClassicWorker()` basée sur la présence fonctionnelle de `globalThis.importScripts`. Dans un Web Worker de navigateur, cette méthode est présente par défaut, ce qui déclenchait la levée de l'exception lors de l'import dynamique de `pyodide.mjs`.
* **Action technique réalisée :** 
  - Neutralisation de la détection classique dans `frontend/js/pyodide-worker.js` en positionnant `globalThis.importScripts = undefined` avant l'import dynamique `await import('/vendor/pyodide/pyodide.mjs')`.
  - Vérification de l'instanciation en Worker `{ type: 'module' }` dans `frontend/js/pyodide-runner.js`.
* **Fichiers modifiés :** `frontend/js/pyodide-worker.js`, `frontend/js/pyodide-runner.js`.
* **Critère de validation :** Exécution 100% fonctionnelle de code Python dans le Web Worker hors-ligne, sans exception console. Validé avec `test_pyodide_offline_assets_served`.

### [x] REV-02 : Rendu Markdown et Typographie des Questions
* **Problème identifié :** Les questions affichaient des balises brutes de Markdown (ex. `**[💻 Laboratoire...]**`, `### Valeur de la fonction...`) avec un texte tassé et des doublons de titres.
* **Cause racine :** Les fonctions de rendu ne géraient pas les titres Markdown (`###`, `##`, `#`), collaient les sauts de lignes sans paragraphes `<p>` et n'extrayaient pas les blocs de code sécurisés.
* **Action technique réalisée :**
  - Implémentation d'un parseur Markdown optimisé `_formatMarkdown` dans `frontend/js/exam-runner.js` et `frontend/js/app.js`.
  - Prise en charge des blocs de code clôturés ```python ... ```, inline code `` `...` ``, titres `###`/`##`/`#`, gras `**`, italique `*`, et structuration des paragraphes avec espacement vertical soigné.
* **Fichiers modifiés :** `frontend/js/exam-runner.js`, `frontend/js/app.js`.
* **Critère de validation :** Affichage aéré, typographiquement élégant et lisible de tous les énoncés sans balises markdown brutes visibles.

### [x] REV-03 : Double Brassage Aléatoire dans les Tests de Niveau
* **Problème identifié :** Dans les Tests de Niveau, ni les questions ni les choix de réponses n'étaient brassés aléatoirement.
* **Cause racine :** L'endpoint `GET /api/practice/exams/{module_code}/questions` renvoyait les questions dans l'ordre séquentiel et les choix bruts sans permutation.
* **Action technique réalisée :**
  - Implémentation du double brassage dans `backend/app/routers/practice.py` : mélange aléatoire des questions via `random.sample` ou `random.shuffle`, et mélange aléatoire des options (`options_copy`) avec conservation de leur identifiant d'origine (`id: str(idx)`).
  - Prise en charge du payload `question_ids` pour évaluer fidèlement l'échantillon exact présenté à l'étudiant.
* **Fichiers modifiés :** `backend/app/routers/practice.py`, `backend/app/schemas.py`, `frontend/js/app.js`, `frontend/js/api.js`.
* **Critère de validation :** Questions et choix mélangés à chaque tentative tout en conservant une évaluation stricte et 100% conforme. Validé par `test_practice_submit_and_instant_scoring`.

### [x] REV-05 : Correction des Questions Vrai / Faux (`boolean`) en Entraînement Python
* **Problème identifié :** Les questions Vrai / Faux dans le centre d'entraînement Python ne s'évaluaient pas correctement ou affichaient des décalages de validation.
* **Cause racine :** Divergence de sérialisation entre chaînes `"true"`/`"false"`, libellés `"Vrai"`/`"Faux"` et booléens natifs, associée à un traitement incorrect des questions typées `yesno`.
* **Action technique réalisée :**
  - Traitement natif des items `raw_type == "yesno"` vers `type: "boolean"` avec options normalisées `{"id": "true", "text": "Vrai"}` et `{"id": "false", "text": "Faux"}`.
  - Normalisation booléenne robuste dans `evaluate_answer` (`grading.py`) et dans la méthode de soumission de session (`training_python.py`).
* **Fichiers modifiés :** `backend/app/routers/training_python.py`, `backend/app/services/grading.py`, `frontend/js/app.js`.
* **Critère de validation :** Sélection, soumission et correction automatique parfaites des questions Vrai/Faux. Validé par `test_grading_boolean`.

### [x] REV-09 : Correction de la Notation des Questions d'Association (Matching)
* **Problème identifié :** Réussir une association complète 4/4 affichait parfois un échec ou 0 point malgré l'explication `4/4 association(s) correcte(s)`.
* **Cause racine :** Décalages de typage/espaces dans les clés de dictionnaires JSON et calcul flottant avec arrondi strict pour déterminer `is_correct`.
* **Action technique réalisée :**
  - Normalisation systématique des clés et valeurs comparées (`str(k).strip() == str(v).strip()`) dans `grading.py`.
  - Règle explicite : `is_exact = (good_matches == total_pairs)`. Si toutes les associations sont correctes, la note maximale est attribuée et `is_correct` est défini à `True`.
* **Fichiers modifiés :** `backend/app/services/grading.py`.
* **Critère de validation :** Association 4/4 validée avec 100% des points et affichage du badge vert ✅. Validé par `test_grading_matching`.
